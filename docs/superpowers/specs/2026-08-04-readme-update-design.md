# README 更新设计

## 目标

根据当前仓库中的 Java 源码、Maven 模块、Spring Boot 自动配置、示例应用和测试，重写根目录 `README.md`。新文档同时服务两类读者：希望快速了解、运行和接入框架的 Java 开发者，以及希望理解模块边界、扩展项目和提交变更的贡献者。

## 写作原则

- 以当前工作区中的实际代码和配置为事实来源，不照搬 `plan.md` 中尚未落地的规划。
- 使用中文撰写，类名、配置键、命令和代码标识符保留原文。
- 先提供可直接执行的快速开始，再补充架构、扩展和贡献信息。
- 不单独维护“已实现 / 未实现”能力清单。
- 对仅存在接口或占位实现的模块使用克制、准确的措辞，不暗示尚不存在的运行能力。
- 不写无法从仓库验证的发布坐标、许可证、兼容性承诺或生产可用性承诺。

## 目标读者与阅读路径

### Java 开发者

开发者应能从 README 中快速确认运行环境，配置 `OPENAI_API_KEY`，构建并启动 `examples/simple-agent`，调用 `/agents/run`，理解响应结构，并找到纯 Java 与 Spring Boot 两种接入方式的关键信息。

### 项目贡献者

贡献者应能从 README 中理解七个 Maven 模块的职责和依赖关系，识别核心 API 与扩展点，掌握常用构建、测试和示例启动命令，并了解代码组织、测试、安全和提交要求。

## 信息架构

README 按以下顺序组织：

1. 项目名称、定位与简短特性概览。
2. 技术栈与环境要求。
3. 项目目录和模块职责表。
4. 快速开始：配置密钥、构建、启动示例、发送 HTTP 请求、阅读返回结果。
5. Java API 使用：创建 `Agent`、构造 `Runner`、执行请求并读取 `RunResult`。
6. Spring Boot 自动配置与 `agents.openai.*` 配置项。
7. 核心概念：`Agent`、`Runner`、`ModelClient`、`Tool`、`Handoff`、`Guardrail`、`SessionStore`、`TraceExporter`。
8. 一次普通文本请求的执行流程。
9. 扩展方式：自定义模型客户端、工具、会话存储和追踪导出器。
10. 构建、分模块测试、完整验证和本地开发命令。
11. 贡献规范与安全注意事项。
12. 当前版本信息，以及仓库未声明许可证时的准确说明。

## 内容边界

文档会描述当前源码中存在的公共契约和可运行路径，但不会将以下内容写成已完成的端到端功能：工具调用循环、反射工具自动创建、Handoff 调度、Guardrail 执行、Session 与 Runner 的自动集成、流式输出，以及完整链路追踪编排。`ReflectionToolFactory.create` 的当前占位行为需要在相关说明中明确，避免示例误导。

README 中的所有命令均以仓库根目录为工作目录。示例默认使用当前配置中的 `gpt-4.1-mini`，API Key 仅通过 `OPENAI_API_KEY` 环境变量提供，不展示或建议把密钥写入配置文件。

## 验证标准

- README 中列出的模块名称、Java 版本、Spring Boot 版本、项目版本、配置键、端点和命令与当前仓库一致。
- Java 示例使用当前真实存在的方法签名，并能由现有模块依赖支持。
- Markdown 相对链接指向仓库中真实存在的文件或目录。
- 文档不包含待补内容、相互矛盾的描述，也不把规划功能表述为现有功能。
- `git diff --check` 通过。
- Maven 全量验证通过；如果外部依赖或网络限制阻止验证，应明确记录实际结果。

实施阶段只修改根目录 `README.md`。本设计说明作为过程记录保存在 `docs/superpowers/specs/`，不修改用户现有的源码、配置、测试、计划文档或未提交变更。
